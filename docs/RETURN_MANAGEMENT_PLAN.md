# 반납 관리

`codex/return-management`에 반납 일정 표시를 구현했습니다. DB 변경·새 RPC·수수료·채팅은 없습니다.

## 화면

`/trades` 상단에 대여 일정 수·오늘 반납·기한 초과 건수를 표시합니다.
반납일 3일 전부터 및 기한 초과 거래를 요약 목록에 표시하고, 내가 빌린 물건/빌려준 물건의 해당 탭으로 이동할 수 있습니다.
받은 요청과 보낸 요청에는 각각 남은 반납일수, 오늘 반납, 기한 초과 일수, 반납 완료를 표시합니다.
승인 전·거절·판매 상품에는 반납 경고를 표시하지 않습니다. 잘못된 날짜는 정보 확인 안내로 구분합니다.

## 알림 범위

- 앱 내 안내만 제공하며 이메일·SMS·푸시를 발송하지 않습니다. 메일 발송 서비스/API 키/스케줄 작업을 추가하지 않았습니다.
- 한국 시간의 날짜로 계산합니다. 반납일 당일은 오늘 반납, 다음 날은 1일 초과입니다.
- 페이지가 열려 있으면 날짜를 30초마다 확인하며, 창 포커스 복귀·탭 활성화 시에도 갱신합니다.
- 다른 사용자가 반납 완료 처리한 데이터는 기존 새로고침 버튼 또는 페이지 재접속으로 갱신합니다.
- 초과수수료 계산·표시는 사용자 요청에 따라 제외했습니다.

## 기존 DB와의 호환

- 기존 요청의 `rental_start_date`, `rental_end_date`, `status`, 연결된 상품의 `trade_type`, `status`만 사용합니다.
- 요청이 `COMPLETED`이면 반납 완료입니다.
- 기존 팀원 코드는 요청을 `APPROVED`로 두고 상품만 `COMPLETED`로 바꾸므로, 이 조합도 반납 완료로 처리합니다. 따라서 반납 후 계속 연체로 표시되지 않습니다.
- 현재 앱의 상품 단위 완료 처리에 맞춘 호환 방식입니다. 향후 동일 상품에 여러 대여 이력을 쌓는 방식으로 바꾸면 요청별 완료 상태를 먼저 정리해야 합니다.
- 기존 완료 버튼의 상품 업데이트 방식을 유지하되, 오류·권한 없음·동시 상태 변경을 확인하고 반복 클릭을 막습니다. 여러 테이블을 변경하거나 트랜잭션 지원을 추가하지 않습니다.
- 공유 DB나 실제 거래 데이터를 테스트 목적으로 변경하지 않았습니다.

## 작업 파일과 병합

계산·표시 코드는 `src/features/returns/**`, 테스트는 `tests/returns/**`에 분리했습니다.
기존 화면 연결은 `src/app/trades/page.tsx`에만 추가했습니다. 지도/인증/상품 등록/카카오톡 안내/기존 DB 정책은 변경하지 않았습니다.
채팅 기능은 팀원의 카카오톡 안내 방식을 사용하므로 추가 구현하지 않습니다.

## 확인 방법

```sh
git switch codex/return-management
npm run dev
```

로그인 후 `/trades`에 접속합니다. 승인된 대여가 없다면 일정 건수는 0입니다.
테스트: `node --test tests/returns/return-status.test.mjs`

- [ ] 내일/오늘/어제 반납일은 각각 1일 남음/오늘 반납/1일 초과로 표시.
- [ ] 반납 완료 처리 후 요약·연체 알림에서 제외되고 카드에 반납 완료 표시.
- [ ] 반납일 누락·잘못된 날짜·비대여·미승인·거절·빈 목록 확인.
- [ ] 기존 사진·인증·카카오톡 동작 유지 확인 후 팀 담당자가 PR을 검토하고 main에 병합.
